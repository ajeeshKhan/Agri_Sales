ABSTRACT

Agricultural trade and information systems in developing agrarian economies suffer from systemic inefficiencies, market fragmentation, severe intermediary exploitation, and lack of direct digital infrastructure. Smallholder farmers frequently receive sub-optimal prices for crop yields due to localized mandi monopolies, opaque broker pricing, and high transportation costs. Concurrently, wholesale buyers encounter inflated prices and inconsistent supply quality, while agricultural input distribution (fertilizers, organic manure, hybrid seeds, and crop medicines) remains disjointed from primary crop trading channels. To address these critical structural challenges, this project presents AgriSales – An Integrated Smart Agriculture Marketplace and Advisory Platform, engineered as a unified, full-stack digital web system using Python 3.14, Django 6.1 framework, and SQLite 3 relational database management.

The AgriSales ecosystem establishes a multi-role digital hub supporting four distinct stakeholder personas: Farmers (Sellers), Wholesale Buyers, Agri-Merchants (Input Vendors), and System Administrators. Farmers can list diverse crop yields (Vegetables, Rice, Food Grains, Fruits, and Pulses) in Indian Rupees (₹/kg) with harvest quality tags, while seamlessly purchasing certified pesticides, fertilizers, and seeds from licensed Agri-Merchants. Buyers navigate an intuitive marketplace featuring interactive quantity pickers (+/- steppers), live dynamic total calculation, a Flipkart-style 4-Step Checkout Accordion (Login -> Address Selection -> Order Summary -> Payment Gateway covering UPI, Cards, Net Banking, and COD with security Captcha verification), and real-time 4-stage logistics timeline tracking.

A core innovation of AgriSales is its automated transaction execution engine: upon checkout confirmation, the system automatically deducts purchased crop quantities from the live inventory database in real time, triggering 'Out of Stock' status guards when stock depletes to zero. Furthermore, an extensive Administrator Console provides comprehensive CRUD control to manage user roles, audit transactions, update item pricing, and eliminate fraud. Empirical system validation and unit testing across Django endpoints confirmed zero migration issues, 100% test case pass rates, and seamless mobile-responsive execution across all viewports.

Keywords: Smart Agriculture Marketplace, AgriTech, Python Django, Multi-Role Access Control (RBAC), Inventory Stock Deduction Engine, E-Commerce Checkout, Digital Agriculture.

CHAPTER 1: INTRODUCTION

1.1 Background

Agriculture remains the backbone of developing economies, supporting over 50% of the rural workforce in South Asia and Latin America. However, traditional agricultural distribution networks rely heavily on multi-layered commission agents, local mandi brokers, and unorganized wholesale traders. This legacy supply chain introduces immense friction: smallholder farmers receive barely 25% to 35% of the final consumer price, while wholesale buyers and end consumers face inflated costs, erratic crop availability, and poor transparency regarding harvest origin. Furthermore, the procurement of essential agricultural inputs—such as bio-pesticides, organic compost manure, hybrid seeds, and plant medicines—is severely fragmented, leaving farmers vulnerable to counterfeit supplies and exorbitant retail markups.

With the rapid surge of digital smartphone adoption and rural broadband connectivity, agricultural technology (AgriTech) platforms have emerged as a powerful solution to disintermediate legacy supply chains. By establishing direct web-based links between producers and purchasers, digital marketplaces enable transparent price discovery, reduce post-harvest food loss, and facilitate fair trade. The AgriSales platform is conceptualized and engineered to address these structural challenges by delivering a unified, web-based e-commerce ecosystem that integrates crop marketplace trading, agricultural input procurement, automated inventory stock management, digital payment gateways, and logistics tracking into a single digital platform.

1.2 Motivation

The primary motivation driving the development of AgriSales stems from the severe economic distress experienced by smallholder farmers due to price manipulation by middlemen and unequal market access. While urban retail commerce has been transformed by modern e-commerce paradigms, agricultural commodity trading in rural sectors remains predominantly offline, manual, and unorganized.

Key motivational drivers include:

  1. Economic Empowerment: Facilitating direct farm-gate sales so farmers capture 100% of their crop listing value without broker deductions.
  2. Supply Chain Streamlining: Enabling wholesale buyers, hotel chains, and retailers to source verified, fresh produce in bulk directly from certified farms.
  3. Integrated Inputs Procurement: Creating a dedicated store for licensed Agri-Merchants to supply high-quality seeds, bio-pesticides, and fertilizers directly to farmers.
  4. Automated Stock Governance: Preventing overselling and stock ghosting through real-time database stock deduction upon payment confirmation.
  5. Full Transparency and Trust: Providing multi-step checkout with multiple payment options (UPI, Cards, NetBanking, COD) alongside live 4-stage logistics status tracking.

1.3 Scope & Objectives

The AgriSales project encompasses the design, implementation, and empirical validation of a full-stack digital web platform built using Python 3.14, Django 6.1 framework, and SQLite 3 database.

Key Project Objectives:

  • To design and implement a robust Role-Based Access Control (RBAC) authentication engine supporting four distinct user roles: Farmer (Seller), Wholesale Buyer, Agri-Merchant, and Administrator.
  • To develop an intuitive Produce Marketplace allowing farmers to list crops (Vegetables, Rice, Food Grains, Fruits, Pulses) with price per kg (₹), harvest quality tags, and live stock tracking.
  • To create a dedicated Agri-Inputs Store for licensed merchants to list bio-pesticides, organic manure, hybrid seeds, and crop medicines.
  • To implement interactive quantity pickers (+/- steppers) with real-time price calculation in Indian Rupees (₹).
  • To engineer a professional Multi-Step Checkout Accordion covering user contact verification, delivery address selection, order item summary adjustment, and multi-mode payment processing (UPI, Card, Net Banking, COD with Captcha).
  • To build an Automated Inventory Deduction Engine that immediately updates relational database stock quantities upon checkout confirmation.
  • To construct an interactive Order Tracking & Logistics Timeline allowing buyers to track their dispatch stage in real time.
  • To deliver an Administrator Console with complete CRUD management capabilities to manage users, edit pricing, update stock, and eliminate marketplace fraud.

1.4 Problem Statement

Existing agricultural commerce models suffer from fundamental structural deficiencies: (a) Information Asymmetry: Farmers lack real-time market price data, making them vulnerable to predatory pricing by commission agents; (b) Procurement Fragmentation: Farmers must navigate disparate physical channels to source farming inputs and sell harvested crops; (c) Lack of Inventory Synchronization: Conventional digital listing boards do not synchronize available inventory with active sales, causing stock overselling and order fulfillment failures; and (d) Inefficient Administrative Control: Platform managers lack centralized tools to audit user credentials, manage listings, and enforce fair trading practices. AgriSales addresses these problems by deploying an integrated Django-backed web platform featuring dynamic stock synchronization, direct payment integration, and administrative CRUD governance.

CHAPTER 2: REQUIREMENTS AND ANALYSIS

2.1 Existing System & Problem Statement

In traditional agricultural trade systems, crop commodities pass through at least 4 to 6 intermediaries before reaching the consumer. Local Mandi aggregators, village brokers, commission agents, regional wholesalers, and local retailers each extract margins, resulting in inflated consumer costs and depressed farm-gate revenue.

Limitations of Existing Systems:

  • Severe Price Manipulation: Middlemen exploit farmers' urgent need for liquidity by offering prices significantly below market rates.
  • High Transaction & Transport Overhead: Duplicate handling and transport legs increase food spoilage and logistics costs.
  • Fragmented Agri-Inputs Market: Farmers frequently purchase low-grade or uncertified pesticides and seeds from unverified local vendors.
  • Manual, Error-Prone Record Keeping: Traditional APMC mandis rely on manual paper receipts, causing settlement delays.

2.2 Solution Overview

AgriSales overcomes these limitations by delivering a full-stack, cloud-ready digital web platform that consolidates crop trading, input procurement, payments, and administrative audit into a single web portal.

3.3 Research Gap & Motivation

A careful synthesis of the existing literature reveals several critical research gaps: (1) Fragmentation of Services: Existing systems treat crop marketplaces, agri-input stores, and expert advisory systems as isolated silos; (2) Absence of Automatic Stock Synchronization: Most agricultural listing portals lack dynamic stock deduction upon checkout, leading to stock ghosting; (3) Lack of Tailored Multi-Role Interfaces: Current solutions offer generic interfaces rather than context-specific, role-themed portals for Farmers, Buyers, Merchants, and Admins; and (4) High Infrastructure Overhead: Enterprise agritech systems require complex Redis/Kafka clusters or IoT hardware not suitable for lightweight rural deployments. AgriSales addresses these exact gaps by delivering a lightweight, integrated, full-stack web platform running on Python Django with automated stock governance and role-tailored user interfaces.

CHAPTER 5: METHODOLOGY

5.1 Module Descriptions

5.1.1 User Authentication & Management Module: Manages multi-role registration, login verification, session management, and dynamic theme switching across the system. (Actors: Farmers, Buyers, Merchants, Admins).

5.1.2 Farmer / Seller Module (Crop Harvest Listing): Empowers farmers to publish crop harvest yields for direct sale to wholesale buyers in ₹/kg with quality tags. (Actors: Farmers).

5.1.3 Buyer / User Marketplace Module: Enables wholesale buyers to discover crops, filter by category tabs, and dynamically select harvest quantities. (Actors: Wholesale Buyers).

5.1.4 Agri-Merchant Input Supplies Store Module: Provides a dedicated store for licensed input vendors to list bio-pesticides, organic manure, hybrid seeds, and medicines. (Actors: Agri-Merchants, Farmers).

5.1.5 Order & Payment Management Module: Processes multi-step buyer checkouts, calculates 5% Mandi Cess tax, and handles payment mode validation (UPI, Cards, Net Banking, COD). (Actors: Buyers, Gateway Engine).

5.1.6 Live Logistics & Order Tracking Module: Displays real-time shipment progress, delivery status timelines, courier truck assignment, and tax invoice generation. (Actors: Buyers, Farmers, Admin).

5.1.7 Expert Consultation & Advisory Module: Facilitates agricultural advisory interactions where farmers seek expert guidance on crop diseases and soil remedies. (Actors: Farmers, Experts).

5.1.8 Administrative Control & Audit Module: Equips system administrators with master CRUD control to audit users, edit pricing, manage stock, and delete accounts. (Actors: System Admins).

5.2 Algorithms & Transaction Logic

Algorithm: DeductInventoryStockOnPurchase(purchased_items_list) Input: Array of purchased items [{id, name, qty}] Output: Updated database stock and status flags 1. BEGIN TRANSACTION 2. FOR EACH item IN purchased_items_list DO: 3. FETCH ProduceItem WHERE id == item.id FOR UPDATE 4. IF ProduceItem EXITS THEN: 5. current_stock = ProduceItem.stock 6. new_stock = MAX(0, current_stock - item.qty) 7. ProduceItem.stock = new_stock 8. IF new_stock == 0 THEN: 9. ProduceItem.tag = 'Out of Stock' 10. END IF 11. SAVE ProduceItem TO DATABASE 12. ELSE: 13. FETCH AgriInput WHERE id == item.id FOR UPDATE 14. IF AgriInput EXISTS THEN: 15. AgriInput.stock = MAX(0, AgriInput.stock - item.qty) 16. SAVE AgriInput TO DATABASE 17. END IF 18. END IF 19. END FOR 20. COMMIT TRANSACTION 21. RETURN Success

5.3 System Architecture

AgriSales adopts a 5-Tier Layered Architecture topology: (1) Presentation Layer (HTML5/CSS3 ES6+), (2) Application Layer (`views.py`), (3) Business Logic & REST API Layer (`urls.py`), (4) Data Access Layer (Django ORM), and (5) Database Layer (SQLite 3 relational DB).

CHAPTER 7: ADVANTAGES & DISADVANTAGES

7.1 Advantages

  1. Complete Disintermediation: Direct farmer-to-buyer sales eliminate broker cuts, increasing farm earnings.
  2. Dual Market Ecosystem: Integrates crop commodity sales with agricultural input procurement.
  3. Dynamic Stock Governance: Automatic database inventory deduction prevents overselling.
  4. Multi-Role RBAC: Tailored dashboards and dynamic CSS theme styling for Farmers, Buyers, Merchants, and Admins.
  5. Enhanced Buyer Trust: Flipkart-style 4-step checkout, multi-mode payment options, and live 4-stage logistics tracking.
  6. Highly Portable Architecture: Self-contained deployment package runnable on any PC via 1-click execution scripts (`run.bat` / `run.sh`).

7.2 Limitations & Constraints

  1. Internet Dependence: Requires active internet connectivity for real-time stock synchronization and checkout APIs.
  2. Localized Prototype Scope: Prototype deployment uses SQLite database, requiring PostgreSQL migration for enterprise-scale multi-region scaling.
  3. Manual Quality Verification: Physical harvest quality inspection relies on farm-gate verification upon delivery.
